# Gemini CLI в Obsidian: установка и настройка

Эта заметка — практический маршрут для тех, кто хочет разговаривать с нейросетью прямо рядом со своими заметками, а не копировать фрагменты из Obsidian в отдельные чаты. Gemini CLI здесь выступает как мост: терминальный инструмент запускается через плагин, а Obsidian остается вашим рабочим пространством с привычными ссылками, проектами и контекстом.

Главная задача гайда — довести установку до состояния, где Agent Client видит Gemini CLI, авторизация работает, а первый запрос можно выполнить без догадок и ручного поиска путей. Поэтому ниже не обзор «AI вообще», а аккуратная последовательность действий: поставить Node.js, установить CLI, авторизоваться, указать путь в плагине и проверить запуск.

Инструкцию лучше воспринимать как базовый старт. Версии пакетов и интерфейсы сервисов могут меняться, поэтому после установки стоит сверить команды с текущей документацией Gemini CLI, а при ошибках идти по шагам из блока Troubleshooting.

## Часть 1: Установка Gemini CLI

Начинаем с обычной, но важной базы. Если CLI не запускается из терминала, Obsidian тоже не сможет надежно вызвать его через плагин, поэтому сначала проверяем системную установку.

### Шаг 1: Установите Node.js (если не установлен)

**macOS:**

```bash
brew install node
```

**Windows:**

- Скачайте LTS версию с https://nodejs.org
- Установите как обычную программу
- Перезагрузитесь

**Проверка:**

```bash
node --version
npm --version
```

### Шаг 2: Установите Gemini CLI через npm

**macOS и Windows:**

```bash
npm install -g gemini-cli
```

**Проверка установки:**

macOS/Linux:

```bash
which gemini
```

Windows (PowerShell):

```powershell
Test-Path "$env:APPDATA\Roaming\npm\gemini.cmd"
```

## Часть 2: Авторизация через Google (OAuth)

Авторизация нужна, чтобы Gemini CLI мог работать от вашего Google аккаунта без ручной вставки ключа в настройки Obsidian. На этом шаге важно не пропустить проверку статуса: если терминал не видит учетные данные, плагин позже будет падать уже внутри Obsidian, и причину сложнее отследить.

### Шаг 1: Авторизуйтесь в терминале

**macOS/Linux/Windows:**

```bash
gemini auth login
```

Откроется браузер — выберите ваш Google аккаунт и подтвердите доступ, если запрос появился.

### Шаг 2: Проверьте авторизацию

```bash
gemini auth status
```

Должно вывести статус типа:

```
✓ Authenticated as: youremail@gmail.com
```

**Файл OAuth будет создан автоматически:**

- **macOS/Linux:** `~/.gemini/oauth_creds.json`
- **Windows:** `C:\Users\YourName\.gemini\oauth_creds.json`

### ⭐ Преимущество OAuth авторизации

| Параметр            | OAuth (Google Account) | API Key (Free)          |
| ------------------- | ---------------------- | ----------------------- |
| **Requests/day**    | 1,000                  | 100-250                 |
| **Requests/minute** | 60                     | 5-15                    |
| **Стоимость**       | Бесплатно              | Бесплатно               |
| **Изменился ли?**   | ❌ Нет (стабилен)      | ✅ Да (снизился 50-80%) |

**Вывод:** для регулярной работы с заметками OAuth удобнее, чем хранить ключ в настройках плагина: авторизация остается на стороне аккаунта Google, а доступный лимит по этой схеме выше. Если Google изменит условия, ориентируйтесь на актуальную документацию, но сама логика настройки останется той же: сначала авторизация в терминале, потом подключение CLI в Obsidian.

## Часть 3: Установка плагинов в Obsidian

Теперь переносим рабочий CLI внутрь Obsidian. Для этого нужен плагин-посредник: он открывает сессию и передает запросы к установленному Gemini CLI, не заставляя уходить из хранилища заметок.

### Шаг 1: Установите BRAT (для beta плагинов)

1. **Settings → Community Plugins → Browse**
2. Поищите **"BRAT"** и установите
3. Включите плагин

BRAT нужен как установщик для плагинов, которые еще не попали в официальный каталог Obsidian. В этом гайде он используется только для Agent Client.

### Шаг 2: Установите Agent Client через BRAT

1. **Settings → Community Plugins → BRAT**
2. Нажмите **"Load from repo"**
3. Вставьте:
   ```
   https://github.com/RAIT-09/obsidian-agent-client
   ```
4. **Install**
5. Включите плагин в **Community Plugins**

## Часть 4: Настройка Agent Client

Самая частая точка ошибки здесь — путь к исполняемому файлу. Obsidian нужно дать не «примерное имя команды», а конкретный файл, который запускает Gemini CLI в вашей системе.

### Шаг 1: Найдите полный путь к Gemini CLI

**macOS:**

```bash
which gemini
```

Пример вывода: `/opt/homebrew/bin/gemini`

**Windows (PowerShell):**
Путь обычно: `C:\Users\YourName\AppData\Roaming\npm\gemini.cmd`

Проверьте:

```powershell
Test-Path "$env:APPDATA\Roaming\npm\gemini.cmd"
```

### Шаг 2: Заполните настройки плагина

Когда путь найден, переносим его в настройки Agent Client. Остальные поля лучше не заполнять без необходимости: в этой схеме авторизация уже прошла через OAuth.

**Settings → Community Plugins → Agent Client**

| Поле                      | Заполнить                 |
| ------------------------- | ------------------------- |
| **Path**                  | Путь к gemini (из шага 1) |
| **Arguments**             | `--experimental-acp`      |
| **API key**               | (оставить пусто)          |
| **Environment variables** | (оставить пусто)          |
| **Enable WSL mode**       | Только если Gemini в WSL  |

**Конкретные примеры:**

macOS:

```
Path: /opt/homebrew/bin/gemini
Arguments: --experimental-acp
```

Windows:

```
Path: C:\Users\SomDev\AppData\Roaming\npm\gemini.cmd
Arguments: --experimental-acp
```

### Шаг 3: Проверьте подключение

Проверка нужна не для формальности: она сразу показывает, где сломалась цепочка — в пути, аргументах, авторизации или самом плагине.

1. **Command Palette** (Ctrl/Cmd + P)
2. Введите: **"Agent Client: Start Session"**
3. Если сессия стартовала без ошибок — связка Obsidian → Agent Client → Gemini CLI готова к первому запросу.

## Часть 5: Первый запуск

После запуска в боковой панели Obsidian появится **"Agent Client"**. Начните с простой команды, которая не меняет заметку и помогает проверить контекст:

```
Напишите: Analyze the current note
Нажмите: Enter
```

Если ответ пришел, можно переходить от теста к реальной работе: просить кратко разобрать текущую заметку, найти противоречия в конспекте, собрать план из связанных материалов или подсказать, какие места требуют уточнения. Ценность связки именно в том, что запрос задается рядом с вашими заметками, а не в пустом отдельном чате.

### Суперспособность: Контекст ваших заметок

Используйте `@`, когда важно не пересказывать модели весь проект вручную. Ссылки помогают направить внимание на конкретные заметки:

```
@[[Project Name]]  или  @note_name

Пример:
"@[[Node.js Guide]] помоги с QUIC используя @network-notes"
```

Такой запрос превращает накопленные материалы в рабочий контекст: Gemini CLI анализирует указанные заметки и отвечает с опорой на них. Чем аккуратнее названы и связаны заметки, тем проще использовать их в диалоге.

## Бонус: Shell Commands плагин (опционально)

Если вы часто повторяете одни и те же запросы, Shell Commands можно использовать как быстрый ярлык. Это необязательный слой: сначала убедитесь, что Agent Client работает, и только потом добавляйте горячие клавиши.

1. **Settings → Community Plugins → Browse**
2. Установите **"Shell Commands"**
3. Создайте команду (в его настройках):
   - macOS: `gemini "your prompt"`
   - Windows: `gemini.cmd "your prompt"`
4. Назначьте hotkey

После этого типовые запросы к Gemini можно запускать из Obsidian одной клавишей, не открывая терминал вручную.

## Troubleshooting

Если что-то не запускается, не меняйте все настройки сразу. Двигайтесь по цепочке: сначала проверьте, находится ли Gemini CLI, затем авторизацию, затем путь в Agent Client.

**"Path to gemini not found"**

```bash
which gemini        # macOS
where gemini        # Windows
```

**"OAuth credentials not found"**

```bash
gemini auth login   # Заново авторизуйтесь
gemini auth status  # Проверьте статус
```

**Windows: gemini не находится**

- Используйте полный путь: `C:\Users\YourName\AppData\Roaming\npm\gemini.cmd`
- Проверьте что файл существует в этой папке
