# Как устроен этот Quartz-сайт Smirnoff

Этот сайт — не чистый Obsidian-vault, который просто выложили в интернет. Quartz здесь работает как статический каркас для сайта Smirnoff: главная, контакты, проектные статьи, юридические документы, библиотека и набор кастомных интерфейсных компонентов.

Markdown остаётся основным форматом для статей. Но самые важные страницы собраны не только из Markdown: часть данных лежит в JSON, а часть поведения вынесена в Preact-компоненты и inline-скрипты.

## Назначение сайта

У сайта несколько задач одновременно:

- показывать услуги и подход к разработке;
- хранить проектные материалы и технические заметки;
- давать понятную навигацию по разделам;
- принимать заявки через форму и callback-механику;
- публиковать юридические документы;
- показывать книжную полку, связанную с BOOK-LIBRARY;
- оставаться статическим сайтом, который можно деплоить на GitHub Pages.

Из-за этого Quartz здесь используется шире, чем обычный «digital garden». Он закрывает и текстовую часть, и интерфейсную.

## Структура content

`content` — источник страниц сайта. Внутри лежат обычные Markdown-файлы и разделы:

- главная страница `index.md`;
- страница библиотеки `library.md`;
- проектные материалы в `Проекты`;
- серия про Obsidian и Quartz в `Проекты/Obsidian`;
- материалы про BOOK-LIBRARY в `Проекты/book-library`;
- юридические документы;
- изображения и вложения, которые используются в статьях.

Quartz читает это дерево, строит slug-и, ссылки, папки, теги, RSS и sitemap. Поэтому структура `content` одновременно влияет и на Obsidian-удобство, и на навигацию сайта.

## Роль quartz.config.ts

`quartz.config.ts` отвечает за то, каким будет сайт при сборке. В текущем проекте там заданы:

- название `Smirnoff`;
- `baseUrl: "slavx.ru"`;
- SPA-навигация;
- popovers для внутренних ссылок;
- Plausible Analytics;
- шрифты Inter и IBM Plex Mono;
- light/dark палитры;
- Markdown-трансформеры;
- emitters для content pages, folder pages, tag pages, RSS, sitemap, static assets и custom OG.

Отдельно важны `FolderPage` и `TagPage` с `usePreviewList: true`. Благодаря этому папки и теги показываются карточками, а не сухими списками.

## Роль quartz.layout.ts

`quartz.layout.ts` отвечает за то, что стоит вокруг контента: левая колонка, правая колонка, общие компоненты и исключения для особых страниц.

В общих компонентах подключены:

- геометрический фон;
- карусель услуг;
- FeedbackForm;
- HomeCallback;
- CookieConsent;
- Footer.

Для обычных статей layout добавляет breadcrumbs, title и meta. Слева находится `Avatar`, мобильный toolbar и `CardMenu`. Справа — поиск, dark mode, reader mode, граф, TOC и Backlinks.

Это важная особенность Quartz: Markdown-файл отвечает за текст, а layout задаёт контекст вокруг него.

## Главная как data-driven лендинг

Главная страница `index` не рендерится как обычная статья. В layout для неё есть `ConditionalRender`, который вставляет `LandingContainer` с блоками из `quartz/static/data/home.json`.

Состав блоков управляется массивом порядка:

- hero;
- focus;
- services;
- works;
- FAQ;
- contact.

Так главная остаётся управляемой данными. Можно менять тексты, карточки, CTA и порядок блоков без превращения `content/index.md` в огромный HTML-шаблон.

На главной также есть отдельный граф и scroll sequence. Это уже не типовая страница Quartz, а полноценный лендинг поверх Quartz-движка.

## Контакты как data-driven страница

Страница `Кoнтакты` устроена похожим образом. Она берёт данные из `quartz/static/data/contacts.json` и собирается из специальных компонентов:

- hero;
- каналы связи;
- workflow;
- форматы старта;
- FAQ;
- CTA.

Это удобно для страницы, где важна структура и интерактивные блоки. Markdown здесь был бы слишком плоским, а JSON + компоненты дают нормальную управляемость.

## Проектные разделы

Проектные статьи остаются ближе к классическому Quartz. Они лежат в `content/Проекты`, получают title, description, tags, preview image и участвуют в графе связей.

Для таких материалов важны:

- аккуратный frontmatter;
- внутренние ссылки через wiki-links;
- короткие descriptions для карточек;
- `preview_image`, чтобы папки и теги выглядели нормально;
- понятная структура папок.

Так сайт работает как база знаний, но не теряет вид обычного публичного сайта.

## Юридические документы

Юридические документы лежат в `content` и публикуются как обычные страницы. Они важны не сами по себе, а в связке с формами и CTA. Если сайт собирает заявку, email, телефон или согласие, рядом должны быть корректные тексты про обработку данных.

Поэтому legal-страницы — часть архитектуры сайта, а не формальность в конце меню.

## Кастомные компоненты

В проекте есть несколько компонентов, которые сильно меняют ощущение от Quartz:

- `Avatar` — визуальная точка входа в левом сайдбаре;
- `CardMenu` — основная навигация вместо Explorer;
- `Search`, `Darkmode`, `ReaderMode` — базовые переключатели;
- `Graph` — граф связей без показа тегов;
- `PagePreviewList` — карточки на страницах папок и тегов;
- `FeedbackForm` — форма заявки через JSON-конфиг;
- `HomeCallback` — callback-механика для лендингов;
- `LibraryPage` — витрина книжной полки.

Часть компонентов рендерит HTML сразу, часть работает как ресурсный placeholder и оживает через inline-скрипт после загрузки страницы.

## Библиотека

`content/library.md` выглядит почти пустым, но это нормально. Для slug `library` layout вставляет `LibraryPage`, который берёт настройки из `bookshelf.json`.

Библиотека показывает категории и книги из BOOK-LIBRARY: сначала пытается работать с live API, а при проблемах может использовать static catalog из `quartz/static/generated`. Обложки могут быть зеркалированы в generated-папку.

Quartz здесь — витрина. Источник истины по книгам остаётся в BOOK-LIBRARY.

## Итог

Этот Quartz-сайт устроен как смесь Markdown-базы и компонентного сайта. Обычные статьи живут в `content`, внешний вид и поведение задаются через `quartz.config.ts` и `quartz.layout.ts`, а сложные страницы собираются из JSON и компонентов.

Такой подход оставляет сайт статическим, но не ограничивает его форматом «страница заметки и список ссылок».
