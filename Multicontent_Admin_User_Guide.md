# Инструкция по работе с Multicontent Admin

## Что это такое

`Multicontent Admin` — локальная админка для редактирования контента:

- главной страницы
- страницы контактов
- категорий мультиконтента
- правил определения источника трафика

Админка работает только локально. В прод она не публикуется.

---

## Что нужно запустить

Открой два терминала в корне проекта.

### 1. Локальный сайт Quartz

```bash
npm run site:dev
```

После запуска сайт будет доступен по адресу:

```text
http://localhost:8080
```

### 2. Локальная админка

```bash
npm run multicontent-admin
```

После запуска админка будет доступна по адресу:

```text
http://localhost:3100
```

---

## Общий порядок работы

1. Запусти `site:dev`
2. Запусти `multicontent-admin`
3. Открой `http://localhost:3100`
4. Измени нужный контент
5. Нажми `Сохранить`
6. Проверь результат в локальном preview
7. Если всё нормально, сделай `commit` и `push`

## Вкладки админки

## 1. Главная

Во вкладке `Главная` редактируется:

```text
quartz/static/data/home.json
```

Можно менять:

- Hero
- Focus
- Services
- FAQ
- Contact CTA

### Что делать

1. Открой вкладку `Главная`
2. Измени нужные поля
3. Нажми `Сохранить`
4. Нажми `Открыть preview`, чтобы проверить главную страницу

---

## 2. Контакты

Во вкладке `Контакты` редактируется:

```text
quartz/static/data/contacts.json
```

Можно менять:

- Hero
- быстрые контакты
- workflow
- formats
- FAQ
- CTA

### Что делать

1. Открой вкладку `Контакты`
2. Измени нужные поля
3. Нажми `Сохранить`
4. Нажми `Открыть страницу`, чтобы проверить страницу контактов

---

## 3. Категории

Во вкладке `Категории` управляются варианты контента главной страницы.

Каждая категория — это отдельный файл:

```text
quartz/static/data/home.<slug>.json
```

Например:

- `home.telegram.json`
- `home.google.json`
- `home.vk.json`
- `home.ad.json`

### Что можно делать

- создавать новую категорию
- выбирать базу для копирования
- менять `label`
- менять `extends`
- редактировать контент категории
- открывать preview категории
- удалять категорию

### Как создать новую категорию

1. Открой вкладку `Категории`
2. В левом блоке `Новая категория` заполни:
   - `Slug`
   - `Label`
   - `Скопировать из`
3. Нажми `Создать категорию`

### Правила для `slug`

Допустимы только:

- маленькие латинские буквы
- цифры
- дефис

Примеры:

- `instagram`
- `vk-retarget`
- `partner-1`

Нельзя:

- `Instagram Ads`
- `реклама`
- `tg source`

### Как редактировать категорию

1. Выбери категорию слева
2. При необходимости измени:
   - `Label`
   - `Extends`
3. Измени контент
4. Нажми `Сохранить категорию`
5. Нажми `Открыть preview`

### Что делает `Extends`

`Extends` задаёт базовую категорию, от которой наследуется контент.

Обычно используется:

```text
default
```

Это значит:

- если в категории нет какого-то поля, оно возьмётся из `default`
- если в категории есть массив, он заменяет базовый массив целиком

### Как удалить категорию

1. Выбери категорию
2. Нажми `Удалить категорию`
3. Подтверди действие

Удаление не сработает, если:

- категория используется в rules
- категория выбрана как `defaultCategory`

## 4. Правила

Во вкладке `Правила` редактируется:

```text
quartz/static/data/multicontent-rules.json
```

Там настраивается, какой трафик попадает в какую категорию.

### Пример логики

- `utm_source=telegram` → `telegram`
- `referrer содержит google.` → `google`
- `referrer содержит vk.com` → `vk`

### Что можно делать

- менять `defaultCategory`
- добавлять новое правило
- менять `priority`
- менять `type`
- менять `param`
- менять `match`
- выбирать категорию назначения

### Как добавить правило

1. Открой вкладку `Правила`
2. Нажми `Добавить правило`
3. Заполни поля:
   - `Priority`
   - `Type`
   - `UTM param`
   - `Match`
   - `Category`
4. Нажми `Сохранить правила`

### Что означают поля

#### `Priority`

Чем меньше число, тем раньше правило проверяется.

#### `Type`

Поддерживаются:

- `utm`
- `referrer`

#### `UTM param`

Обычно:

```text
utm_source
```

#### `Match`

Для `utm`:

```text
telegram
```

Для `referrer`:

```text
google\.
vk\.com
t\.me|telegram
```

#### `Category`

Категория, контент которой нужно показать.

---

## Как работает preview

Preview нужен для проверки конкретной категории вручную.

Пример:

```text
http://localhost:8080/?_mc_preview=telegram
```

Preview:

- принудительно показывает выбранную категорию
- не должен менять сохранённый first touch
- нужен только для проверки

---

## Какие файлы реально меняются

Админка меняет только файлы в:

```text
quartz/static/data/
```

Основные:

- `home.json`
- `contacts.json`
- `home.<slug>.json`
- `multicontent-rules.json`
- `multicontent-meta.json`

## После редактирования

После любых изменений:

1. Проверь сайт локально
2. Убедись, что нужная категория открывается через preview
3. Проверь страницу контактов, если менял `contacts.json`
4. Сделай `git status`
5. Сделай `commit`
6. Сделай `push`

## Полезные сценарии

## Добавить новый рекламный источник

1. Создай категорию, например `instagram`
2. Настрой контент категории
3. Перейди в `Правила`
4. Добавь правило, например:
   - `type = utm`
   - `param = utm_source`
   - `match = instagram`
   - `category = instagram`
5. Сохрани правила
6. Проверь:

```text
http://localhost:8080/?_mc_preview=instagram
```

## Изменить только тексты для Telegram-трафика

1. Открой `Категории`
2. Выбери `telegram`
3. Измени Hero / Focus / CTA
4. Сохрани
5. Проверь:

```text
http://localhost:8080/?_mc_preview=telegram
```

## Изменить дефолтный контент для всех

1. Открой `Главная`
2. Измени `home.json`
3. Сохрани
4. Проверь обычную главную:

```text
http://localhost:8080/
```

---

## Ограничения

- Админка локальная, не продовая
- Контакты редактируются, но не маршрутизируются по источнику трафика
- Если категория используется в rules, удалить её нельзя
- `default` удалять нельзя

---

## Если что-то не работает

Проверь по порядку:

1. Запущен ли `npm run site:dev`
2. Запущен ли `npm run multicontent-admin`
3. Открывается ли `http://localhost:3100`
4. Открывается ли `http://localhost:8080`
5. Есть ли ошибки в терминале админки
6. Не сломан ли JSON после ручных изменений
