# Инструкция по работе с Multicontent Admin

## Что это такое

`Multicontent Admin` — локальная админка для редактирования контента:

- главной страницы
- страницы контактов
- категорий мультиконтента для главной
- правил определения источника трафика

Админка работает только локально. В прод она не публикуется.

---

## Что нужно запустить

Открой два терминала в корне проекта.

### 1. Локальный сайт Quartz

```bash
npm run site:dev
```

После запуска сайт будет доступен по адресу:

```text
http://localhost:8080
```

### 2. Локальная админка

```bash
npm run multicontent-admin
```

После запуска админка будет доступна по адресу:

```text
http://localhost:3100
```

---

## Общий порядок работы

1. Запусти `site:dev`
2. Запусти `multicontent-admin`
3. Открой `http://localhost:3100`
4. Измени нужный контент
5. Нажми `Сохранить`
6. Проверь результат в локальном preview
7. Если всё нормально, сделай `commit` и `push`

---

## Как теперь работать с категориями

Отдельной вкладки `Категории` больше нет.

Категория выбирается прямо в шапке админки, в блоке `Категория для редактирования`.

Что это значит:

- выбрал `Основная` — редактируешь обычный `home.json`
- выбрал `telegram`, `google`, `vk` и т.д. — редактируешь соответствующий `home.<slug>.json`
- формы в `Главная` остаются теми же, меняется только активный вариант контента

### Как переключить текущую категорию

1. В шапке найди блок `Категория для редактирования`
2. Нажми на нужную категорию
3. После переключения открой вкладку `Главная`
4. Редактируй Hero / Focus / Services / FAQ / Contact CTA как обычно

### Как создать новую категорию

1. В шапке нажми `Новая категория`
2. В модальном окне укажи:
   - `Slug`
   - `Название`
   - `Создать на основе`
3. Нажми `Создать и переключить`
4. После этого админка сразу переключится на новый вариант

### Как удалить категорию

1. Переключись на нужную категорию в шапке
2. Нажми `Удалить текущую`
3. Подтверди действие

Удаление не сработает, если:

- категория используется в rules
- категория выбрана как `defaultCategory`

### Правила для `slug`

Допустимы только:

- маленькие латинские буквы
- цифры
- дефис

Примеры:

- `instagram`
- `vk-retarget`
- `partner-1`

Нельзя:

- `Instagram Ads`
- `реклама`
- `tg source`

## Вкладки админки

## 1. Главная

Во вкладке `Главная` редактируется текущая выбранная категория.

Если в шапке выбрана `Основная`, сохраняется:

```text
quartz/static/data/home.json
```

Если выбрана рекламная категория, сохраняется:

```text
quartz/static/data/home.<slug>.json
```

Можно менять:

- Hero
- Focus
- Services
- Works / Кейсы
- FAQ
- Contact CTA

Редактор внутри вкладки разбит на субвкладки по блокам, чтобы не работать с одной длинной формой.

### Что нового в редакторе

- для цветовых вариантов карточек и сервисов есть визуальная палитра
- для Material-иконок есть picker с поиском и предпросмотром
- выбор иконки делается не по названию вслепую, а из визуального списка

### Что делать

1. Открой вкладку `Главная`
2. Выбери нужную субвкладку: `Hero`, `Focus`, `Services`, `Works`, `FAQ` или `Contact CTA`
3. Измени нужные поля
4. Нажми `Сохранить`
5. Нажми `Открыть preview`, чтобы проверить текущую категорию

### Hero / первый экран

В субвкладке `Hero` редактируется первый экран главной страницы для текущей выбранной категории: обычный `home.json` или конкретный `home.<slug>.json`.

Базовые поля:

- `Fallback title` — запасной обычный заголовок `hero.title`. Он нужен для совместимости и используется, если `titleParts` пустой или в варианте категории нужно намеренно заменить составной заголовок простой строкой.
- `Badge / pill` — короткая плашка над заголовком. Хорошо работает как 3–7 слов: направление, оффер или главный контекст варианта.
- `Подзаголовок` — основной поясняющий текст под заголовком. Лучше держать его в 1–2 предложениях без длинных перечислений.
- `SLA строка` — короткое обещание реакции или процесса, например `Ответ в течение дня`.
- `Текст primary CTA` и `Текст secondary CTA` — подписи кнопок. Держи их короткими, чтобы кнопки не переносились и не ломали сетку.

#### `titleParts` и accent

`titleParts` — составной заголовок hero. Каждая часть содержит:

- `text` — фрагмент текста;
- `accent` — чекбокс `Синий accent`, который подсвечивает фрагмент акцентным цветом.

Как использовать:

1. Разбей заголовок на 2–4 смысловые части.
2. Включи `accent` только на ключевой фразе, которую нужно выделить.
3. Не делай акцентом весь заголовок: визуально лучше работает один короткий фрагмент.
4. Если в конкретной категории задаёшь только `hero.title` без `titleParts`, runtime покажет простой заголовок и не унаследует старые `titleParts` из базовой категории.

Рекомендации по длине:

- весь заголовок — примерно до 70–90 символов;
- акцентная часть — 1–4 слова;
- не вставляй длинные переносы вручную: компонент сам балансирует строки.

#### Subtitle и tags/chips

`Подзаголовок` объясняет оффер, а `Chips` (`hero.tags`) — короткие теги под ним.

Рекомендации:

- 3–5 chips на экран;
- один chip — 1–3 слова или очень короткая фраза;
- не дублируй в chips весь подзаголовок;
- для рекламных категорий меняй chips под источник трафика: `Telegram`, `CRM`, `MVP`, `Оплаты`, `SEO` и т.д.

#### Benefits

`Benefits` — список коротких преимуществ под chips. У каждого пункта есть:

- `Иконка` — Material Symbol из picker;
- `Текст` — короткий результат или преимущество.

Лучше использовать 2–4 пункта. Длинные предложения здесь смотрятся хуже, чем короткие benefit-labels: `Интеграции с CRM`, `Быстрый запуск MVP`, `Админка для команды`.

#### Dashboard visual

`Dashboard visual` управляет правой визуальной частью hero на desktop/tablet. На mobile dashboard скрывается стилями, чтобы первый экран не становился слишком длинным и не ломал чтение.

Поля dashboard:

- `Visual title` — заголовок внутри карточки dashboard.
- `Tab` (`hero.visual.tabs`) — вкладки в верхней панели. Держи 2–4 коротких labels: `Overview`, `Leads`, `Revenue`.
- `Metric` (`hero.visual.metrics`) — карточки метрик:
  - `Label` — короткое название метрики;
  - `Value` — значение;
  - `Delta` — изменение или пояснение;
  - `Tone` — цветовой тон `blue`, `green`, `orange` или `purple`;
  - `Sparkline points` — числа для мини-графика.
- `Integration` (`hero.visual.integrations`) — чипы интеграций с `Иконка` и `Label`.
- `Automation` (`hero.visual.automations`) — строки автоматизаций с `Иконка`, `Label`, `Value`, `Status`.
- `Side card` (`hero.visual.sideCards`) — боковые карточки с `Иконка`, `Title`, `Text`.

Рекомендации по визуалу:

- labels в tabs, metrics, integrations и automations должны быть короткими;
- не добавляй слишком много элементов: 3 metrics, 5–7 integrations, 2–3 automations и 2–3 sideCards обычно достаточно;
- `Sparkline points` заполняй небольшим набором чисел, например `10, 16, 13, 22, 19, 30`;
- `Text` в sideCards делай в одну короткую строку или компактное предложение;
- если dashboard не нужен для конкретной категории, оставь структуру базовой категории через наследование, а не создавай пустые длинные массивы.

#### Preview и переключение категорий

Переключение категории в шапке админки обновляет редактор текущего `Hero`, а preview через `_mc_preview=<slug>` показывает hero выбранной категории. Поэтому после изменения hero обязательно проверь именно нужную категорию кнопкой `Открыть preview`, а не только дефолтную главную.

### Works / Кейсы

В субвкладке `Works` редактируется блок `03 / Кейсы` из `home.json` или текущего `home.<slug>.json`.

Что можно менять:

- заголовок и индекс секции
- список кейсов `works.items`
- у каждого кейса: `id`, `badge`, `title`, `active`
- изображения слайдера: `dark`, `light`, `alt`, `width`, `height`
- кнопки nav: Material-иконка `icon` и `label`
- карточки: `variant`, `cornerIcon`, `labelIcon`, `label`, `title`, `description`

Для тёмной и светлой темы у слайда заполняются отдельные поля `dark` и `light`.

У каждого поля изображения есть:

- текстовое поле для ручного ввода URL или пути, например:

  ```text
  /images/Prodject/Audio-Scribe/1d.webp
  ```

- кнопка `Выбрать файл`, которая открывает проводник файлов
- preview текущего изображения прямо в админке

Как загрузить изображение через проводник:

1. Открой `Главная` → `Works`
2. Найди нужный кейс и нужный слайд
3. В поле `Dark image` или `Light image` нажми `Выбрать файл`
4. Выбери PNG, JPEG, WebP или GIF до 10 MB
5. После загрузки админка автоматически подставит путь вида:

   ```text
   /images/Prodject/uploads/works/<safe-name>.<ext>
   ```

6. Preview обновится сразу после загрузки
7. Нажми `Сохранить`, чтобы путь попал в `quartz/static/data/home.json` или текущий `home.<slug>.json`

Файлы сохраняются в проекте в папку:

```text
content/images/Prodject/uploads/works/
```

Preview также обновляется при ручном изменении URL в поле `dark` или `light`, поэтому можно по-прежнему вставлять готовые пути без загрузки файла.

## 2. Контакты

Во вкладке `Контакты` редактируется:

```text
quartz/static/data/contacts.json
```

Можно менять:

- Hero
- быстрые контакты
- workflow
- formats
- FAQ
- CTA

Редактор внутри вкладки тоже разбит на субвкладки по секциям страницы.

### Что делать

1. Открой вкладку `Контакты`
2. Выбери нужную субвкладку: `Hero`, `Быстрые контакты`, `Workflow`, `Formats`, `FAQ` или `CTA`
3. Измени нужные поля
4. Нажми `Сохранить`
5. Нажми `Открыть страницу`, чтобы проверить страницу контактов

---

### Палитра и выбор иконок

Для полей `Цвет` в карточках и сервисах доступны визуальные варианты:

- `Blue`
- `Purple`
- `Orange`
- `Green`

Для Material-иконок в админке есть picker:

1. нажми на поле `Иконка`
2. откроется текущая иконка и список доступных значков
3. при необходимости введи текст в поиск
4. кликни по нужной иконке

Picker используется там, где на сайте рендерятся Material Symbols:

- карточки `Focus`
- иконки результата в `Focus`
- иконки в `Services`
- шаги `Workflow`

Для быстрых контактов в `contacts.json` выбор ограничен безопасными вариантами:

- `send`
- `mail`
- `call`

### Как удалить категорию

1. Выбери категорию
2. Нажми `Удалить категорию`
3. Подтверди действие

Удаление не сработает, если:

- категория используется в rules
- категория выбрана как `defaultCategory`

## 3. Формы

Во вкладке `Формы` редактируются endpoint и метод отправки:

```text
quartz/static/data/home-callback-form.json
quartz/static/data/feedback-form.json
```

Доступны две субвкладки:

- `Home callback` — форма обратного звонка
- `Feedback / бриф` — большая форма брифа

Что можно менять:

- `Action / endpoint`
- `Method` (`POST` или `GET`)
- `Submit label`
- `Privacy note`
- `Title`
- `Subtitle`

Поля формы (`fields`) в этой версии админки сохраняются без изменений.

## 4. Правила

Во вкладке `Правила` редактируется:

```text
quartz/static/data/multicontent-rules.json
```

Там настраивается, какой трафик попадает в какую категорию.

### Пример логики

- `utm_source=telegram` → `telegram`
- `referrer содержит google.` → `google`
- `referrer содержит vk.com` → `vk`

### Что можно делать

- менять `defaultCategory`
- добавлять новое правило
- менять `priority`
- менять `type`
- менять `param`
- менять `match`
- выбирать категорию назначения

### Как добавить правило

1. Открой вкладку `Правила`
2. Нажми `Добавить правило`
3. Заполни поля:
   - `Priority`
   - `Type`
   - `UTM param`
   - `Match`
   - `Category`
4. Нажми `Сохранить правила`

### Что означают поля

#### `Priority`

Чем меньше число, тем раньше правило проверяется.

#### `Type`

Поддерживаются:

- `utm`
- `referrer`

#### `UTM param`

Обычно:

```text
utm_source
```

#### `Match`

Для `utm`:

```text
telegram
```

Для `referrer`:

```text
google\.
vk\.com
t\.me|telegram
```

#### `Category`

Категория, контент которой нужно показать.

## Как работает preview

Preview нужен для проверки конкретной категории вручную.

Пример:

```text
http://localhost:8080/?_mc_preview=telegram
```

Preview:

- принудительно показывает выбранную категорию
- обновляет Hero, Focus, Services, Works, FAQ и Contact CTA для выбранного варианта
- не должен менять сохранённый first touch
- нужен только для проверки

Если переключить категорию в шапке админки и нажать `Открыть preview`, ссылка откроется уже с нужным `_mc_preview=<slug>`. Это основной способ проверить, что новый hero, dashboard, chips и CTA действительно относятся к выбранной категории.

## Какие файлы реально меняются

Админка меняет только файлы в:

```text
quartz/static/data/
```

Основные:

- `home.json`
- `contacts.json`
- `home.<slug>.json`
- `home-callback-form.json`
- `feedback-form.json`
- `multicontent-rules.json`
- `multicontent-meta.json`

## Полезные сценарии

## Добавить новый рекламный источник

1. Создай категорию, например `instagram`
2. В шапке переключись на неё
3. Настрой контент категории во вкладке `Главная`
4. Перейди в `Правила`
5. Добавь правило, например:
   - `type = utm`
   - `param = utm_source`
   - `match = instagram`
   - `category = instagram`
6. Сохрани правила
7. Проверь:

```text
http://localhost:8080/?_mc_preview=instagram
```

## Изменить только тексты для Telegram-трафика

1. В шапке выбери `telegram`
2. Открой `Главная`
3. Измени Hero / Focus / CTA
4. Сохрани
5. Проверь:

```text
http://localhost:8080/?_mc_preview=telegram
```

## Изменить дефолтный контент для всех

1. Открой `Главная`
2. Измени `home.json`
3. Сохрани
4. Проверь обычную главную:

```text
http://localhost:8080/
```

---

## Ограничения

- Админка локальная, не продовая
- Контакты и формы редактируются, но не маршрутизируются по источнику трафика
- В Works изображения можно задавать как URL/пути и загружать через локальную админку
- Если категория используется в rules, удалить её нельзя
- `default` удалять нельзя

---

## Если что-то не работает

Проверь по порядку:

1. Запущен ли `npm run site:dev`
2. Запущен ли `npm run multicontent-admin`
3. Открывается ли `http://localhost:3100`
4. Открывается ли `http://localhost:8080`
5. Есть ли ошибки в терминале админки
6. Не сломан ли JSON после ручных изменений

Если нужно техническое описание системы, смотри:

`Multicontent_Implementation_Guide.md`
